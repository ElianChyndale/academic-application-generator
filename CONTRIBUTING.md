# Contributing

Contributions must keep the project offline, deterministic, evidence-bound, and
public-safe.

1. Use a focused branch.
2. Add or update a source before changing a claim.
3. Regenerate fixtures, schemas, materials, research outputs, and reports.
4. Run pytest, Ruff, strict mypy, every CLI command, and a clean-wheel audit.
5. Explain any claim-state, programme-source, or public-output change.

Do not commit private application data, transcripts, grades, contact details,
recommendation letters, secrets, absolute local paths, fabricated achievements,
or live application credentials. Do not add network calls, form submission,
email sending, professor selection, or admission scoring to the default flow.
